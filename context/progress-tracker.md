### 2026-09-28 - Admin report page adopts the adviser report presentation

- **One component, two roles.** `AdviserReportReview` gains `role?: "adviser" | "admin"`, mirroring `ReportDetailHeader`'s existing `role` prop. `/admin/departments/[deptId]/reports/[eventId]` now renders `role="admin"` instead of its own `ReportViewer` layout, so the event header, unresolved-overspend disclosure and control-number panel match the adviser view exactly.
- **Read-only by construction, not by flag.** `role="admin"` forces `canReview` false, so the Approve/Reject buttons *and* the decision dialog are omitted entirely — following the project's read-only convention of omitting rather than disabling, and making it impossible to pass `role="admin"` and still get deciding controls.
- **Destination links suppressed for admin.** The department workspace has no `expenses` / `budget-history` / `spending-summary` / `previous-revisions` / `signed-report` sub-routes, so the folder cards and rows are not rendered. Rendering links that 404 would be worse than omitting them. Adding the admin sub-routes is a separate follow-up; when they exist this is a one-line change.
- **Paths derive from `event.department_id`** — back goes to `/admin/departments/[deptId]?tab=reports` and View Event to `/admin/departments/[deptId]/events/[eventId]`. The workspace page's `initialTab` previously only honoured `tab=users` and silently fell back to Events, so `?tab=reports` was added; without it the back link would have landed on the wrong tab.
- **Data is now department-scoped.** `getLatestReportByEvent` → `getAllReportsByEvent(eventId, departmentId)`, which filters through `events!inner(department_id)`. `[0]` is still the newest report of any status including cancelled, so the honest-badge behaviour is preserved.

### 2026-09-27 - Archived events expose the uploaded Signed Report

- **New destination for both roles.** "Signed Report" appears in the report workspace nav for treasurer and adviser, shown **only when `event.status === "archived"`** — before archiving there are no pages to show, and an empty link would be a dead end. It leads to `/treasurer|adviser/reports/[eventId]/signed-report`, which lists the pages uploaded at archive time and opens the shared `ImageViewer` on tap.
- **A proxy had to be built first.** The `signed-reports` bucket is private and the SDK exposes no signed URLs, so page images are streamed by a new session-authed route `GET /api/reports/[reportId]/signed-page?i=N`, mirroring `api/entries/[entryId]/image`: resolve report → event, `requireRole(["treasurer","adviser","admin"], event.department_id)`, stream the blob. Both new pages keep `requireRole(<role>)` plus the explicit cross-department `notFound()` before any read.
- **Replaced a broken unused helper.** `lib/storage.ts` had `getSignedReportUrl`, unreferenced, which returned `URL.createObjectURL(blob)` — a server-side object URL, explicitly forbidden by the storage rules and useless as a URL. It is now `getSignedReportPageBlob(reportId, index)`, returning a blob and reading the key from `signed_document_urls` rather than rebuilding `{deptId}/reports/{id}/page-N.jpg`, so it cannot drift from what was actually uploaded.
- **Page count comes from the stored keys,** not `signed_page_count` — that column records the count the AI verified, while the array is what was stored; the array is authoritative for rendering.
- **Page images stay native `<img>`** with `alt`, `loading="lazy"` and `decoding="async"`, matching the documented receipt-image precedent: session-proxied, variable size, `object-contain`. One `@next/next/no-img-element` warning is expected and intentional.

### Receipt parsing — final fast-path design (2026-09-05, user-verified closed)

- **Model is NOT the bottleneck:** `gemini-3.5-flash-lite` pinned since 08-02 (bench: ~2–3s at ANY resolution — prompt tokens pinned ~1065, Gemini resamples internally; at 1024 it GARBLES text, SVG source leaked). Root cause of the 18s was the pipeline: the route uploaded the image, inserted a provisional row, then `getReceiptBlob` downloaded it back just to build a data URL — storage round-trips on a cold Hobby function blew the 8s budget and the client retry doubled it.
- **`app/api/entries/receipt/route.ts` (final):** feed the already-client-compressed multipart `File` DIRECTLY to Gemini (data URL from `image.arrayBuffer()` — no storage read); Gemini + `requireRole` start concurrently; the blob upload runs after auth, overlapping the model call (still needed for the retry path + `image_url`); on success insert straight to `ai_parsed` (single insert, no provisional hop). Verdict → delete blob + 422 + audit; duplicate → delete blob + 409; transient Gemini failure → insert `pending_ai_parse` (blob already uploaded) + audit so the retry route works. Critical path ≈ 3–4s warm. **`app/api/entries/receipt/[entryId]/route.ts` is the retry endpoint** — on a transient `{status:"parsing"}` the client re-parses the SAME provisional row from its stored blob (no re-upload, no duplicate blob).
- **Constants (all still in place):** `lib/gemini.ts` `TIMEOUT_MS = 8_000` (Vercel Hobby has a hard 10s function ceiling — a 9s timeout risks the kill; room must stay for cold-start). `lib/image.ts` `MAX_DIM = 1600`, JPEG q `0.8` (legibility; the 1280/0.7 "fewer tokens = faster" theory was measured wrong and reverted). `MAX_ATTEMPTS = 2` (primary + 1 reparse). `agent/receipt-parser.ts`: transport/timeout errors (`GeminiError`, `TimeoutError`, `AbortError`, `/aborted|timeout|timed\s?out/i` via `isTimeoutError`) are NON-retryable — throw immediately; the 3-attempt budget is preserved ONLY for fast zod/schema-mismatch re-parses (model already returned).
- **Orphan leak fixed (09-04):** verdict-422 AND duplicate-409 branches must delete the provisional row — shared `discardProvisional(insforge, entryId, imageUrl)` helper (DB delete that THROWS on failure so it can't silently orphan, + best-effort blob delete). A failed parse never leaves an untitled ₱0.00 `pending_ai_parse` row.
- **[SUPERSEDED]** 09-04 two-phase upload (202 + poll, `POLL_DELAY_MS=1500`) — shipped, then killed: it regressed perceived time to ~20s (3 attempts × Gemini + sleeps). The single-request fast path above supersedes it. Deploy note for the two-phase era is in Notes.

### Classification (guided upload) — rules that never change

- Outcomes: `valid` / `borderline` / `invalid` / `multiple`. Doubt → `borderline`, never `invalid`. Verdicts short-circuit with guidance + audit, NO Entry row, and never count toward the 3-attempt ceiling. Only `valid` creates a row (at `ai_parsed`). `multiple` (2+ distinct documents, even partially visible; hand/fingers ≠ second document; doubt resolves by document count) → 422 `entry.receipt_multiple_documents`, "One receipt per upload" banner + mobile hint.
- `document_type_raw` = verbatim printed label, never forced into an enum; `""` when none (handwritten). `document_number` tied to that label; `""` when no label-tied number — never null, never made up (numberless receipts skip the duplicate check). `amount` = Final Amount Due, never sub-total. `item_breakdown` required. Category inferred at parse time (7-way: transportation/meals/honorarium/supplies/printing/rental/others; doubt → `others`); AI final, review read-only, no backfill.
- Duplicate check: reject if `(document_type_raw + document_number)` already exists in the same event.
- Upload pipeline: client-side downscale via shared `lib/image.ts` (≤1600px longest side → JPEG q0.8, `createImageBitmap` with `imageOrientation: "from-image"`, white-composited for PNG transparency, HEIC/HEIF + <1MB pass through untouched, any failure returns the original — downscale is an optimization, never a blocker). Database `entries.status` IS CHECK-constrained (see Notes — AGENTS.md claim of free text is wrong).
