### Bottom-sheet gesture suite (2026-09-07 — final state; iteration history below in the supersede chain)

- **Sheet grab rule (final):** a down-drag grabs the sheet ONLY at content-top (`scrollTop <= 0`). At the content end, down-drags now scroll content back up (fixes "i cant scroll up when i scroll down"). Close is via the top-band fling or the close button — long forms (Log Entry, Archive/Void, ReceiptReview) no longer pull-to-close from the content end. File: `components/ui/CssBottomSheet.tsx` + `lib/bottom-sheet-drag.ts`.
- **Dismiss rules:** `MIN_SHEET_DRAG = 4` — a dismiss is honored only once the sheet is genuinely displaced past 4px; a pure-scroll gesture (offset ≤ 4) snaps back to TOP and never closes. `resolveReleaseTarget`: fling down > 0.8px/ms OR slow release at/past 50% of sheet height → dismiss (`onClose`); fling up < −0.8px/ms → top snap (ease `0.22,1,0.36,1`); slow release before the line → spring back with overshoot (ease `0.34,1.56,0.64,1`) to the snap the gesture STARTED from (`startSnapRef` at pointerdown — not nearest-snap). `settleDrag` re-entry guard `if (activePointer.current === null) return;` (Chrome fires `pointerup` then an eventless `lostpointercapture`; re-resolving from MID-rest offset wrongly dismissed).
- **Touch pipeline (the "moves slightly then snaps back" fix):** Chrome claims vertical pans over `overflow-y-auto` bodies (default `touch-action`) and fires `pointercancel`; `setPointerCapture` on a touch pointer fires spurious `lostpointercapture`+`gotpointercapture` mid-gesture; repeated capture to root relocates the touch. Fixes: per-mount effect sets `touch-action: none` on EVERY descendant (touch-action is not inherited; browser fully out of the gesture path, content scrolls via the JS handoff branch), explicit `setPointerCapture` only for `pointerType !== "touch"` (touch uses implicit capture + bubbling through the sheet root). 8px engage gate protects taps.

Exit slide-down plays because consumers always-mount the sheet: `EntryList.tsx` renders `<EntryDetailModal open={!!selectedEntry} entry={selectedEntry}>` and the modal latches the last non-null entry via the render-time pattern `const [lastEntry, setLastEntry] = useState(entry); if (entry && entry !== lastEntry) setLastEntry(entry); contentEntry = entry ?? lastEntry` (strict eslint bans `useEffect`+`useState` for this). `if (!contentEntry) return null;` goes AFTER all hooks.

### Classification (guided upload) — rules that never change

- Outcomes: `valid` / `borderline` / `invalid` / `multiple`. Doubt → `borderline`, never `invalid`. Verdicts short-circuit with guidance + audit, NO Entry row, and never count toward the 3-attempt ceiling. Only `valid` creates a row (at `ai_parsed`). `multiple` (2+ distinct documents, even partially visible; hand/fingers ≠ second document; doubt resolves by document count) → 422 `entry.receipt_multiple_documents`, "One receipt per upload" banner + mobile hint.
- `document_type_raw` = verbatim printed label, never forced into an enum; `""` when none (handwritten). `document_number` tied to that label; `""` when no label-tied number — never null, never made up (numberless receipts skip the duplicate check). `amount` = Final Amount Due, never sub-total. `item_breakdown` required. Category inferred at parse time (7-way: transportation/meals/honorarium/supplies/printing/rental/others; doubt → `others`); AI final, review read-only, no backfill.
- Duplicate check: reject if `(document_type_raw + document_number)` already exists in the same event.
- Upload pipeline: client-side downscale via shared `lib/image.ts` (≤1600px longest side → JPEG q0.8, `createImageBitmap` with `imageOrientation: "from-image"`, white-composited for PNG transparency, HEIC/HEIF + <1MB pass through untouched, any failure returns the original — downscale is an optimization, never a blocker). Database `entries.status` IS CHECK-constrained (see Notes — AGENTS.md claim of free text is wrong).

- Adviser batch-approve dispatches `executeBatchApprove` (the dialog once dispatched `executeUserAction`, which no-ops without `userId`). Rejection reason threads to `EntryDetailModal` red callout. `entryTitle()` = supplier → "Category — detail" → category → "Untitled entry".

### Reports (Phase 7–9) — rules that never change

- **Reports are never overwritten:** regeneration after rejection/cancellation creates a NEW row reusing the same `fs_document_number` with `revision_count` incremented (audit-only, never printed). `getAllReportsByEvent` = full history ordered `generated_at` desc; newest drives the precondition gate, "Previous revisions" card lists the rest.
- **FS number anchored per EVENT:** number = first-assigned `fs_document_number`; suffix increments per event via dept/year counter (`FS-{DEPTCODE}-{YYYY}-{00001}`); cancelled/rejected regenerations never consume a new number.
- **Lifecycle groups:** treasurer — `Needs attention` (no report OR newest `rejected`; newest `cancelled` collapses to "No report yet" via `getLatestReportsByEvent` dropping it to null; its PDF stays reachable on the detail page's Previous revisions) → `Pending approval` → `On file` (`approved`, event still open) → `Archived` (event `archived`, always carries an approved report; read-only). Adviser — `Pending approval` → `Reviewed` (`approved`/`rejected` trail) → `Archived`; excludes no-report events.
- **Cancel:** treasurer-only, dept-scoped, event not archived, `pending_adviser_approval` only, race-guarded (racing approve → 409); no adviser cancel notification. **Reject:** whole report re-visible + re-generable; rejected PDF stays listed.
- **PDF UX:** reports are downloadable documents, not inline renders — `PdfViewer.tsx` deleted (pdfjs-dist NOT Node-safe — `DOMMatrix` at module scope crashes SSR on static import; dynamic `await import` inside the render effect + `GlobalWorkerOptions.workerSrc` from a module constant was the fix; pdfjs-dist left in `package.json` unused to avoid churn). `ReportFileCard.tsx` (server component) everywhere: View = `?inline` (default) / Download = `?dl=1` → `Content-Disposition: attachment` via `app/api/reports/[reportId]/pdf/route.ts`. `pdf_url` stores the storage KEY, never a browser-loadable URL — proxy streams. `reports` orders by `generated_at` (no `created_at`).
- **Generation (Step 20) discoveries:** no `router.refresh()` after generate (kills client preview); cross-user notification inserts silently failed → added `notifications_same_dept_insert` RLS policy. Signatories client-only (localStorage) until the report is persisted. Signatory columns wrap at 3 per row (`flexWrap:"wrap"` + `width:"33.33%"`). Note: codebase uses `insforge.database.from(...)`.
- **Archive (Step 25):** `requireRole("treasurer")`; guards → 404 (no event / wrong dept), 403 (no latest approved report), 409 (already archived or `has_unresolved_overspend`); uploads each signed page (`uploadSignedReport(report.id, i+1, file)`), `countPdfPages` = regex on `/Type /Pages … /Count N` (fallback 1 — pdfjs-dist client-only), then `verifySignedDocument` (agent/document-verifier.ts: gpt-4o via OpenRouter, 3 attempts; checks fs_document_number + signature-like marks per `report_signatories` ordered by `sort_order` + page count — **completeness only, never authenticity**); fail → best-effort delete uploaded keys + 422 with per-check `checks`/`summary`; pass → race-safe event update `.eq("id").eq("status","open")` (0 rows → 409 + rollback) + `signed_document_urls`/`signed_page_count`/`signing_confirmed_by|at` + audit `event.archived`. `canArchive = latestReport?.status === "approved" && !isArchived && !event.has_unresolved_overspend`.
- **@react-pdf/renderer:** server-side only, `renderToBuffer` only, in `app/api/reports/generate`; buffer → storage directly (never disk); supported CSS subset listed in AGENTS.md/library-docs.

### Signup & auth (final state after the 08-31/08-30/08-22 work)

- **Wizard:** 3 steps (Name → Account(email/password) → Council(role/dept)), forward-only (top arrow = back to `/login`), per-step gating via the `submitted` red-border pattern, `stepError` vs `apiError` distinct states. Step 2 `POST /api/auth/signup` = validation-only gate (required fields, IP rate limiter, `check_signup_email` → "Email already exists", client email regex `EMAIL_RE = /^[^\s@]+@[^\s@]+\.[^\s@]+$/` + 8-char password gate) — NO account creation, NO email. Step 3 `POST /api/auth/signup/complete` = the SINGLE point the account is born + the OTP email fires (re-checks same gates, purges any `in_progress` ghost, calls `signUp`, resolves/auto-seeds department). Step-aware back nav + reload-safe step index + per-email OTP cooldown survives back-nav (`signup_otp_sent` timestamp drives the `/otp` countdown). 409 "just started" dead-end fixed: re-proceed on an `in_progress` account routes to `/otp` (original OTP still valid — ghosts purge ~10min, OTP 15min; InsForge keeps ONE `email_otps` row per email+purpose, so no double-send).
- **Approver notifications fire post-OTP:** the `users` row only exists after `POST /api/auth/create-profile` runs `create_user_profile` — the old pre-OTP notify block could never find the adviser (`get_user_department_id()` → NULL). Notifications now run in `create-profile` AFTER the row exists: treasurer → dept's active adviser; adviser → all active admins.
- **Login lockout v2 (cycles):** `lib/rate-limit.ts` email bucket, 3-cycle state machine (`mode: "cycles"`): C1 = 5 fails → 1 min, C2 = 3 fails → 5 min, C3 = 3 fails → 24h soft lock (cooldown rides `IDLE_TTL_MS`; on lift the staleness check wipes the bucket same-request — no one-fail-from-relock zombie); cycle counters reset on each cooldown trip; stale buckets (>24h idle) restart at C1; success clears everything; `softLocked: true` JSON flag + inline login modal → `/forgot-password`. Redemption: `/api/auth/change-password` calls `clearRateLimit("e:{email}")` after successful `resetPassword` (safe — requires OTP + inbox). IP bucket stays the flat ladder: `baseMs × 2^(failures − threshold)`, cap 30min email / 1hr IP, threshold email 5 / IP 15 (IP key = `xff first hop ?? x-real-ip`; bucket skipped entirely when neither header exists); 429 + `Retry-After` before InsForge is touched; success clears only the email bucket (typos forgiven); 403s (pending/rejected accounts) never count; blocked requests never extend timers. In-memory ceiling accepted: resets on deploy, per-instance — a DB-backed table is the documented upgrade path. Signup IP bucket: `SIGNUP_IP_LIMIT`, threshold 10/min, cap 15 min, cleared wholesale on successful creation.
- **Session:** `proxy.ts` (Next 16) — `updateSession` runs FIRST so redirect decisions use the real post-refresh token; refresh cookie `insforge_refresh_token` = 2 days (`REFRESH_COOKIE_MAX_AGE`, Max-Age beats Expires per RFC 6265), re-pinned on every navigation via `updateSession` → sliding window; `user_role` cookie 7d (cosmetic redirect hint must outlive the window); away >2 days → re-login (one constant). Browser client auto-refresh via `POST /api/auth/refresh` (`createRefreshAuthRouter`). OTP verify manually persists access/refresh cookies (SSR client never writes response cookies). `middleware.ts` is deprecated vs Next 16 `proxy.ts`.
- **Foundational (07-17/07-18):** OTP 10-min expiry, resend 60s, max 5/hour, 5 wrong attempts lock. Verified OTP → stays `pending_approval` → `/pending-approval`. Admin accounts never via `/signup` (role selector excludes Admin client-side AND server-side). `api/auth/status` polling (10s) → redirect/banner + nodemailer welcome email on approve. Dept auto-seeds on first signup. `/forgot-password → /otp?purpose=reset → /change-password → /login`.
- **Optimistic UI (08-31):** admin + adviser approve/reject are instant — remove the row on click, run the server action async in the background, roll back on failure, `router.refresh()` on success. `window.confirm` REMOVED (the "dead air"; an accidental Reject now purges — rollback only guards server preconditions).
